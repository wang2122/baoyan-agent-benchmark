### S0
先说一个可能缓解你焦虑的判断：**面试老师要听的不是"这个项目多厉害"，而是"你在里面做了多深"。** 参与型项目只要边界清楚，得分往往高于含糊其辞的"主导"——因为后者一旦被追问就穿帮，而穿帮的代价是整份材料的可信度归零。

---

## 一、不能动的底线：口径一致

简历、个人陈述、面试口述、（若有）推荐信，对同一个项目的角色描述必须完全一致。**参与的项目在任何场合都不能升级为主导**。这是唯一一个"错了就没法补救"的地方，其他都是表达技巧问题。

反过来说，主动写明边界是加分项，它传递两个信号：你懂工程协作，你有技术自知。

---

## 二、取舍：三问筛选法

对每个项目问三句话：

| 问题 | 含义 |
|---|---|
| ① 我能白板画出系统框图，并指出每个模块的输入输出吗？ | 深度是否够被追问 |
| ② 有没有属于我个人的、可量化的产出？ | 贡献是否可证 |
| ③ 和目标院校/课题组方向相关吗？ | 是否有匹配价值 |

- ①②③ 全中 → **主导项目**，详写，占简历项目篇幅的主体
- ①② 中、③ 不中 → **参与项目**，2–3 行精简呈现
- 只有 ② → 一句话带过（如获奖栏一行），或直接删
- ① 都答不上 → **删**。挂名项目留在简历上只有风险没有收益

**数量控制**：一页简历，项目 2–4 个，其中详写的主导项目 1–2 个。宁可两个讲透，不要六个泛泛。高度同质的项目（比如三次同类型竞赛）合并成一条，写"三次参赛，最好成绩 X，负责模块从 A 演进到 B"，反而体现成长曲线。

## 三、呈现：两套模板

### 主导项目（详细版）

结构是：**角色行 → 技术决策 → 量化结果 → 沉淀**

```
RoboMaster 机甲大师赛 · 视觉组负责人（团队 28 人，视觉组 4 人）
- 主导哨兵自瞄系统重构：将原单目模板匹配改为装甲板检测 + EKF 弹道预测，
  命中率 41% → 78%
- 独立完成相机–云台手眼标定，重投影误差 < 1.2 px，标定耗时 25 min → 6 min
- 沉淀为组内可复用标定工具与训练流水线，被后续两届沿用
- 2025 全国赛一等奖（主力队员）
```

要点：
- **动词要具体**：主导 / 独立实现 / 重构 / 推导 / 标定，而不是"负责""参与""协助"
- **每个技术选择都配一个"为什么"**：上面写了"从模板匹配改为检测+EKF"，你就必须能回答"原方案在什么工况下失效"。写不出原因的技术名词就别写
- **量化优先**：精度、耗时、代码量、数据规模、团队人数、你在其中的位次
- **沉淀最加分**：能被后人复用的工具/文档/流水线，说明你做的不是一次性作业

### 参与项目（精简版）

```
XX 四足机器人地形适应项目 · 参与成员（5 人团队，本人负责足端力传感数据采集与标定）
- 搭建力传感采集台架，采集并标注 12k 条足端触地数据，为组内接触检测模型提供训练集
- 成果：XX 竞赛省一等奖（团队成员）
```

要点：
- **角色行里就把边界钉死**："本人负责 X 模块"，不写"参与整个项目"
- 只写你亲手做的事，团队的总体成果放在最后一行、明确标注是团队成绩
- 2–3 行封顶。它的作用是证明你有工程经历和协作能力，不是主战场

## 四、面试防御：三类必问

**1. 三个"为什么"**
- 为什么用这个方法？
- 为什么不用另一个（更常见/更简单的）方案？
- 如果重做一遍，你会改哪里？

第三问最能区分"真做过"和"挂名"。真做过的人一定有遗憾。准备 1–2 个具体的失败尝试和它们的教训——这比只讲成功更有说服力。

**2. 边界追问**
> "这部分是你做的吗？"

如果**不是**，标准答法是：**诚实否认 + 展示你了解接口和全局**。
> "控制律不是我设计的，是队友 X 负责的。我的力传感数据是作为接触状态输入给他的模块，我了解它的输入输出定义和大致思路（比如用了 XXX），但具体参数整定我不清楚。"

这个答法不会扣分。含糊其辞或强行揽功才会。

**3. 基础原理反查**
简历上出现的每一个词都可能被拆到最底层：写了 ROS 就要能讲 TF 树和消息机制，写了卡尔曼滤波就要能手推预测/更新两步，写了 SLAM 就要能讲清后端优化在优化什么。**写不上白板的东西，从简历上删掉。**

## 五、方向匹配：一份简历不够用

排名 [个人排名已概括] 是你的硬通货，六级 [英语成绩已概括] 够用但不突出，所以**项目是你唯一的差异化武器**，必须对准靶子用。

同一个项目，投不同方向时改写重心：
- 投**控制**方向 → 强调控制律设计、稳定性、参数整定过程
- 投**感知**方向 → 强调传感器融合、标定、数据处理与模型
- 投**机构/本体**方向 → 强调结构设计、动力学、加工工艺

准备 2–3 个版本的简历。联系导师前先看其近 3 年论文，邮件里建立连接："我在 XX 项目中做了 YY，遇到 ZZ 问题，看到您在 …… 的工作，想了解……"——这种邮件的回复率远高于通用模板。

## 一、先定性：你手里其实有三类东西

| 类别 | 你的情况 | 归属栏位 | 写法基调 |
|---|---|---|---|
| A. 主导型项目 | 之前提的那几个机器人项目里你能独立扛住追问的 | **科研项目 / 项目经历** | 详写，技术决策 + 量化结果 |
| B. 大项目中的子模块 | 老师大项目里的子模块 | **科研项目 / 项目经历** | 借势大项目，但角色行钉死到子模块 |
| C. 未展开的兴趣方向 | 机器人子方向A（具体名称已概括）、机器人子方向B（具体名称已概括） | **技能栏 / 个人陈述 / 导师邮件** | 写成"方向"，不写成"项目" |

关键区分：**A、B 是"做过的事"，C 是"想做的事"。这两类混在一栏里，是简历最常见的失分点。**

---

## 二、B 类：大项目里的子模块

### 先纠正两个相反的错法

- **错法一（夸大）**：写成"参与 XX 项目"甚至"负责 XX 项目"。老师一追问主系统架构你答不上，整个简历的可信度崩掉。
- **错法二（自我贬低）**：写成"负责一个子模块的制作"。你把一个完整的工程闭环讲成了打杂。

**"子模块"如果是你从需求到验证独立走完的，它就是一个完整闭环——而这恰恰是导师最想看到的能力证明。一个闭环的小东西，胜过一个模糊的大项目。**

### 核心技巧：先写"为什么需要这个装置"

同一个装置，两种写法：

> ❌ 设计并制作了一个标定装置，完成了加工与装配。

> ✅ 主系统在 XX 工况下无法直接测量 YY，需专用装置提供 ZZ 基准；独立完成该装置方案设计与验证。

差别在于：前者是"我做了个东西"，后者是"我判断出系统缺什么，并补上了"。**后者展示的是工程判断力，不是动手能力。** 这是 B 类项目最大的一次升级。

### 模板

```
XX 大学 XX 实验室 XX 项目（国家自然科学基金 No.XXXXXX，负责人：X 教授）
· 本人角色：XX 装置设计与实现（项目子模块，独立完成）

- 需求来源：主系统在 XX 工况下无法直接测量 YY，需专用装置提供 ZZ
- 方案设计：完成结构方案与刚度/公差校核，电机与传感器选型，
  控制板与上位机通讯协议定义
- 实现验证：加工、装配、标定；重复定位精度 ±0.05 mm，满足主系统 XX 指标
- 交付沉淀：装置已投入课题组日常使用，输出装配图与操作文档
```

要点：
- **借势但不越位**：项目来源和负责人写清楚（这是可信度背书），角色行精确到"子模块"
- **有指标**：装置类项目最容易写成流水账，一个精度/量程/ repeatability 数字能立刻把它拉回工程语境
- **有交付**：被课题组持续使用，比任何形容词都硬

### 面试必被问的三题

1. **"整个大项目是做什么的？"** → 准备 30 秒版本：目标、技术路线、你的装置在哪一环。这题答不好，前面的借势全部反噬。
2. **"你的装置和主系统的接口是什么？"** → 机械、电气、数据三个接口都要能说清。这是证明你真的在系统里，而不是 isolated 地做了个手工件。
3. **"这装置有什么不足？"** → 准备真实的局限（精度受限于 X、只覆盖 Y 工况、没做温度补偿）。能讲局限的人才像真做过的人。

对主系统其他部分，用**诚实边界 + 接口层认知**："那部分不是我做的，我了解它对外的接口定义和大致思路，具体内部实现我不清楚。"

## 三、C 类：机器人子方向A（具体名称已概括）、机器人子方向B（具体名称已概括）——不要进项目栏

### 为什么

"了解阶段、还没正式展开"写进项目栏，只有一个后果：老师问"你做了什么"，你答"还没开始"。**这一问一答会让他回头怀疑你其他项目的成色。** 空口说兴趣是负分。

### 那它该去哪

**① 技能栏（诚实标注状态）**
```
ROS 2 / MoveIt 2（自学中：已完成官方教程，搭建 Gazebo 仿真环境）
```
标注"自学中"不丢人，反而是可信度来源。

**② 个人陈述的"研究兴趣"段——这才是它的主场**

结构是：**方向 → 我已经做的最小准备 → 我想解决的具体问题**

> 我对 XX 方向有兴趣，目前已读完 XX 等 3 篇工作并复现了其中的 YY 部分。我注意到的一个具体问题是 ZZ，希望在研究生阶段深入。

**"我想解决的具体问题"这一句，是区分"泛泛有兴趣"和"真的入门了"的分水岭。**

**③ 联系导师的邮件——价值最高的位置**

导师筛学生时，关心的是"你想做什么、和我们组对不对得上"，而不是"你做完过什么"。一个方向明确、有准备动作的学生，比一个项目很多但方向发散的学生更有吸引力。

### 把"了解"变成"可谈"：低成本升级动作

现在它之所以危险，是因为**没有任何可展示的实体**。花一到两周就能改变这一点：

- 读完 2–3 篇该方向的近期论文，能讲清一个具体的技术问题
- 跑通一个开源 baseline 或官方 tutorial
- 搭好仿真环境（Gazebo / Isaac Sim / MuJoCo）
- 装好 ROS 2 + MoveIt 2，跑通一个 demo

做完任意两项，它就从"我感兴趣"变成了"我可以和你讨论"——这时候放进个人陈述就完全站得住。

## 四、一个需要你自己想清楚的问题

**"机器人子方向A（具体名称已概括） + 机器人子方向B（具体名称已概括）"是两件事，还是一件事？**

- 如果是**两个独立兴趣**捆在一起写，老师会看出你还没想清楚自己要什么。机器人子方向A（相关控制与感知）和机器人子方向B（相关运动规划与操作）是两条差异很大的技术路线。**挑一个作为主方向，另一个作为相邻兴趣提一句。**
- 如果其实是 **机器人子方向A + 机器人子方向B（具体名称已概括）的组合系统**，那它有正式名字：**[具体研究领域名称已概括]**，是一个真实的研究领域，有自己的顶会 track 和综述。**能准确说出这个领域名，本身就是一个强信号**——说明你不是在拼凑关键词，而是知道文献在哪。

这两种情况的最优写法完全不同，先自己定下来。

## 五、时点与行动建议

现在是 10 月中旬，推免系统已开放、多数院校复试接近尾声。分两种情况：

**如果你是 2026 届、正在补录或联系导师阶段：**
- B 类项目今天就按上面模板重写，这是零成本高收益
- C 类**从简历里拿掉**，改写进个人陈述的兴趣段；如果来不及做准备动作，就一句都不提
- 面试重点放在 B 类的三道必问题上

**如果你是 2027 届、为明年做准备：**
- **最优策略是把 C 类做成真的。** 一个"从自学了解到实际落地"的完整过程，本身就是最好的项目——而且它天然是你主导的，不存在贡献边界问题
- 时间充裕，按第四节的判断选定方向，然后走完：调研 → 仿真 → 实物 → 验证
- 同时争取把 B 类装置做得更深（加一轮迭代、写一份正式技术报告、甚至产出专利或论文），明年它就能从 B 类升到 A 类

---

**一句话总结：B 类要放大（它是完整闭环，别自我贬低），C 类要移位（它是方向不是项目，放个人陈述和导师邮件里），两者绝不能混在同一栏。**
