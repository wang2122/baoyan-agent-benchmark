### S0
这个担心很常见，而且值得现在就处理：面试官一定会挑你简历上的 1–2 个项目往深里追问，所以取舍的核心标准不是“项目大不大、听着强不强”，而是**哪个项目你能在三层追问下站得住**。

## 一、取舍：用“三层追问测试”筛项目

对每个项目自问三层：

1. 第一层：项目解决什么问题？系统整体是怎么跑通的？
2. 第二层：你负责的部分在系统里处于什么位置？你的技术选型是什么、为什么这么选？
3. 第三层：关键参数怎么定的？指标怎么测出来的？印象最深的 bug 是什么？如果把你去掉，项目会受什么影响？

- 三层都能答 → **旗舰项目**，放简历最前面详写，面试主推。
- 第一、二层能答，第三层只能答一部分 → **支撑项目**，如实写你负责的模块，不展开讲系统全貌。
- 第二层就卡住（说不清自己具体做了什么，分不清调库和自己写的）→ 降级为成果列表里的一行（如仅保留获奖），或不写。

简历上保留 2–3 个能深讲的项目即可，其余压缩。项目多而都浅，等于主动给面试官递刀。

## 二、“负责”与“参与”的呈现方式

角色标签要统一、如实、可辩护，三档对应不同写法：

- **负责人/队长**：整体方案、分工、进度都算你的，可以讲全系统。
- **核心成员，负责 X 模块**：写清模块边界和团队规模，例如“5 人团队，负责感知模块的相机标定与点云滤波部分”。
- **参与者，完成 X**：如实承认参与性质，但把 X 写成具体交付物，如“完成底盘运动学建模与 PID 整定，将轨迹跟踪横向误差从 X cm 降到 Y cm”。

反面清单：不写“参与项目开发”这类空话；不把团队成果默认归自己；任何数字必须能解释测量方法，解释不了就删掉数字。

## 三、简历项目段的模板

```
项目名 | 角色(负责人/核心成员-负责X模块/参与-完成X) | 时间
- 一句话背景与目标
- 2–3 条"我做了什么":动词开头 + 具体技术点 + 可辩护的量化结果
- 成果:实物演示 / 获奖等级 / 报告或代码链接
```

## 四、面试准备：每个项目一页“防守稿”

- 系统架构图（要能在白板上手画）
- 你的模块在架构中的位置
- 2–3 个关键技术决策及备选方案的对比理由
- 指标及测量方法
- 一个真实的坑和解决过程（必须出自你自己的工作）
- 预判问题清单：尤其“这部分具体是你做的吗”“为什么不用 XX 方案”“这个库的哪些部分你改过”

每个项目准备 30 秒、2 分钟、可展开 5 分钟三个版本。找同学互相深挖演练一遍，守不住的当场降级。

## 五、组合成一条主线

把项目串成指向你报考方向的主线（如运动控制、SLAM、具身智能）：旗舰项目打主方向，支撑项目补相邻能力面（感知/控制/嵌入式）。与主线无关、又没有奖项加持的项目可以删。自我介绍也用这条线串，这样“项目组合”本身就成了你的故事，而不是一堆零散条目。

## 六、诚实红线

面试官识破夸大的方式就是追问细节，被抓一次比项目少更伤。另外简历内容要与报名系统提交的材料一致，部分院校会复核。

最后说一句你的整体盘面：前约2% 的排名已过绝大多数学校的硬门槛，六级 500–549 也不构成限制，项目和面试表现就是你真正的差异点——现在花在“防守稿”上的功夫是回报最高的投入。

### S1
这三类内容要分三个池子处理，核心判断标准只有一条：**简历“项目”栏只放有你亲手完成、可验证产出的东西。**“了解阶段”是动机和学习，不是项目。

## 一、小装置：这是你最硬的项目素材，建议升格

在老师大项目里负责一个小装置，恰恰是你能完全 ownership 的东西——它小到你能讲清楚从需求到落地的每一步，扛得住上次说的“三层追问”。这比“参与了一个大项目”更可信。

**写法建议**（角色标签如实，边界写清）：

```
XX课题组XX项目 | 负责XX装置的设计与实现 | 时间
- 一句话:该装置在大项目中的作用(解决什么问题)
- 2–3 条你亲手做的:方案选型/结构或电路设计/调试与验证
- 成果:装置是否投入使用/通过什么测试/老师或团队的反馈
```

**面试防守要点**：讲这个项目时主动划定边界——“大项目的整体方案是老师定的，我负责其中 X 装置从选型到调通的完整过程”。主动划界比被追问出来体面得多，而且“小而完整”正是导师看重的执行力证据。如果这个装置和你报考方向（比如机械、电控、感知）相关，它可以当旗舰项目用；如果相关度一般，也是强支撑项目。

## 二、无人机+机械臂项目：现在不进简历

还没正式展开，就没产出可验证，写上去只有两个结局：面试时被问“具体做了什么”答不上，或者你自己主动讲“还在了解阶段”——两种都比不写伤。所以：

- **简历项目栏：不写。**
- **它真正该出现的地方是个人陈述/研究计划/面试问答**：作为你的研究兴趣和规划——“我在调研无人机与机械臂协同方向，研究生阶段希望深入”。展示的是方向感和主动性，这和项目经历是两回事，混在一起反而两头受损。

两个时间点上的处理：

1. **如果你在某批次材料提交前，这个项目已经正式展开**（比如暑期真做起来了），可以列为“在研”，如实写当前阶段和你承担的部分，并准备好“目前进展到哪一步”的回答。每一批提交的材料和系统内容要同步更新、保持一致。
2. **让它升级的最省力路径**：现在花点时间跑通一个仿真 demo（如 ROS/Gazebo 里的机械臂运动规划或无人机仿真）。到面试时它就能从“了解阶段”变成“已完成入门实践”，从只能出现在研究计划里，变成可以讲的实战内容——这是当前性价比最高的一步棋。

## 三、简历项目区的排序

按“完整度×相关度”排：自己主导的完整项目 → 课题组的装置（如实标注负责模块）→ 其他已完成的参与项目。了解阶段的一律不占项目区版面。

一句话总结：**装置是项目，写深；无人机+机械臂是方向，写进规划；了解，不写成经历。**
